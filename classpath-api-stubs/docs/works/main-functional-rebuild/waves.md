## Release and conflict rules

Only a `completed` Result with the stated evidence satisfies an item. The containing gate checks that evidence and releases only explicit dependents. `partial`, `blocked`, `failed` or missing evidence never release a gate. The Router retrieves full Results after completion notifications and projects truthful state before release; Handlers do not join/wait, delegate or release later work. This document is not an automatic scheduler or an additional approval process.

Docs items consume the full completed matching code Result and confirm current main still has that exact candidate SHA/tree and unchanged tested code/build/version inputs. They write and stage only their listed ordinary-documentation paths, then make a separate signed commit and verify it. They do not run builds, repair code, change versions or edit Specs/PRDs/ADRs or historical authority. Missing passing evidence, changed candidates or non-doc staged content block docs; a documentation commit never substitutes for code evidence. Disclose unrelated remaining formatter/XML state without staging or discarding it. Code Results leave matching documentation commits to their docs owner; a completed code item alone does not release its feature gate.

All items conflict through shared Git/history/source ownership and, when used, Gradle/GPG resources. Run the chain serially; no simultaneous signing, builds, worktree/index changes or shared-source edits. Source worktrees and frozen refs are read-only except the narrowly captured preservation operation; existing original branch tips must not move. No authority edits, new Tasks, unsigned commits, remote publishing, tags or pushes.

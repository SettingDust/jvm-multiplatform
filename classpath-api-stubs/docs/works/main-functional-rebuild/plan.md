## Strategy and invariants

Recoverability precedes destruction. Preserve original refs, each dirty feature's exact bytes on dedicated local recovery branches/commits, documentation (including this untracked tuple), root maintenance, and inheritance formatting. Prove every valuable path is retrievable before resetting main. No external archive dumps or stash-based implicit recovery. Keep generated IDEA XML in place with hash evidence and, if needed, an exact local exclusion list.

Use the exact frozen three merge sources, not moving branch names. Every merge is an explicit signed merge retaining the feature tip as an ancestor, with conflict resolution preserving base Code/actual behavior. Integrate metadata from all original inputs into the N-way intersector; retain only current-entry full nodes while using cheap headers for ancestry. Preserve uncached byte streams, Object termination, cache tracking and viable TestKit launcher setup. Replaying mixed old integration commits or overwriting shared files wholesale is not acceptable.

The dedicated preservation branches may descend from old main. Never merge that old-main ancestry into rebuilt main: transplant only the captured feature delta onto a new integration branch based on current rebuilt main, with signed commits, then merge that branch signed. The original recovery refs remain intact. This prevents silently reintroducing the old combined integration through an unrelated feature recovery.

Each remaining feature has two serial, independently observable outcomes: its original code item integrates and verifies a signed candidate; its separate docs item consumes that completed Result and commits only truthful matching ordinary documentation, signed. They require different Handlers/Results, with no docs-commit requirement in a code Result and no code repair or build execution in a docs Result. The containing feature gate requires both completed Results; the following feature's code waits for the preceding docs, and final audit waits for plugin docs. Waves alone defines the IDs, prerequisites, ownership and release predicates. This corrects the rejected compound inheritance Handoff without changing accepted behavior or verification.

Do not batch feature docs ahead of merges or report feature/gate completion before both Results exist. Preserve base docs already in history. After-base branch-sync docs are historical evidence: restore their content in ordinary documentation with explicit historical context after the relevant feature; worker docs own cross-feature reconciliation. Do not delete/archive files, edit historical authority or turn historical plans/pending Spec text into fresh completion claims. The tuple first entered main as planning context in the inheritance docs item and is now recorded by signed commit `7a79d220a8114c275ff05536c4148963a78f4738`; it remains in-progress Plan context rather than final clean-state evidence. Its pre-reset safety commit lives only on recovery refs and is not a completed-feature docs commit. Pending plans remain untracked through code delivery and are staged only by their docs owner.

Apply the classpath version once with inheritance and retain it through later classpath merges; apply the FIR and actual versions with their owning feature deliveries. Root settings, formatting, docs and `.gitkeep` do not trigger other version changes.

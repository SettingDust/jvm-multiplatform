# Internal Host Input Bridge for Preserve Actual Matching

Status: **Proposed, non-authoritative; never accepted.** This is a historical alternative, not a pending implementation prerequisite: the plugin-only code/test fix has since merged into local main as `78af72cf3132cee3830a16bd173ade0bb9a2632b` with fixture-bounded P4 evidence in [Work](../works/preserve-actual-matching/work.md). No host bridge was approved or implemented. This document does not amend the [accepted Spec](../spec/preserve-actual-matching.md), approve a replacement Plan, or claim production acceptance beyond the recorded fixture. The Spec limits implementation to the compiler plugin and tests and explicitly excludes source-set orchestration and Cloche. The existing Work and [verification record](../works/preserve-actual-matching/verification.md) retain the execution history.

## Historical decision requested

Allow the existing Cloche common-stub `KotlinCompile` and virtual-source-sets linkage to supply a verified, invocation-scoped input bridge for the stub compiler plugin, extending internal implementation ownership beyond `kmp-actual-stubs/compiler-plugin` to Cloche and `virtual-source-sets/gradle-plugin`. Keep one existing compilation task, the current public options, compiler 2.2.20, strict diagnostics and all A1-A15 obligations. Do **not** treat a boolean attestation as proof or install the experimental preprocessor by default. No authority or implementation changes follow merely from writing this proposal.

At the time of this proposal, without this permission production delivery remained blocked until a plugin-only mechanism proved equivalent complete, stable input/content/fragment identity at the early decision point. Those early experiments had not done so; the two bounded late candidates failed, but this was **not** proof that every possible plugin-internal solution was impossible. Subsequent plugin-only implementation and P4 fixture checks resolved the in-scope delivery without this bridge. A compiler-phase hook/new driver or upgrade remains a larger, unverified direction requiring a separate decision, not an implicit fallback.

## Evidence and limits

The [real-host report](../../../../../jvm-multiplatform-actual-matching/kmp-actual-stubs/compiler-plugin/build/host-closure-probe/report.zh-CN.md) used an isolated Gradle 9.2.0 / Kotlin 2.2.20 `compileKotlin`, the actual virtual-source-sets plugin sources, a generated actual attached with `builtBy`, and a stub jar built with KSP/AutoService. With full input declared and `incremental=false`, the mixed case succeeded: the actual body returns 73 and the distinct missing declaration throws `UnsupportedOperationException("Common modules are not runnable")` in inspected bytecode. The control **actually ran** a separately packaged `PreprocessedVirtualFileFactoryExtension`: without the stub plugin, its added actual `absent()=91` was matched and emitted, despite no second actual on disk; with the integrated prototype and an incorrect content attestation, unchanged roots/fragment inputs led to ABSENT and `ACTUAL_WITHOUT_EXPECT`/`CONFLICTING_OVERLOADS`. This third-party extension is a deliberate counterexample, **not** a default component of the Cloche task. The report also records an un-attested default-incremental rejection and a source-classifier `Token` case that stayed UNKNOWN/`NO_ACTUAL_FOR_EXPECT` even with full inputs. See the [integrated prototype report](../../../../../jvm-multiplatform-actual-matching/kmp-actual-stubs/compiler-plugin/build/integrated-bridge-probe/report.zh-CN.md): exact root/graph pairing and native source/module identity are partial safeguards, but the prototype reads disk text and binds identities as callbacks arrive. Neither experiment is production implementation or complete acceptance.

The original repository root build still fails at `settings.gradle.kts:8:36: Unresolved reference 'file'.` Isolated KSP packaging and a real Gradle consumer do not clear this **separate** root-build obstacle. These reports, fixtures and run logs live under the other worktree's ignored `build/`; they can disappear on cleanup and are not durable tests committed to main.

## Candidate internal ownership and contract

These are candidate touchpoints grounded in existing source, **not** a claim that the necessary APIs or bridge already exist:

| Candidate owner | Existing responsibility and proposed change |
| --- | --- |
| [Cloche `CommonTargetCreator.kt`](../../../../../cloche/src/main/kotlin/earth/terrarium/cloche/target/common/CommonTargetCreator.kt) (`createCommonTarget` / `addCompilation`) | Common main/client/data/test source-set setup and per-source-set `PLUGIN_CLASSPATH_CONFIGURATION_NAME` currently add the stub plugin dependency. Limit bridge admission to these existing common stub tasks; arrange their internal task inputs and compiler-side handoff here if feasible. Do not change Java annotation processing or platform targets. |
| [`JavaVirtualSourceSetsPlugin.kt`](../../../../virtual-source-sets/gradle-plugin/src/main/kotlin/net/msrandom/virtualsourcesets/JavaVirtualSourceSetsPlugin.kt) (`addKotlinCommonSources` / `addDependency`) | Currently calls `compileTask.source(kotlinDependency.kotlin)` and builds `-Xfragments`, `-Xfragment-refines`, `-Xfragment-sources`, `-Xcommon-sources` via providers, using `sourceDirectories.asFileTree` for metadata. Reconcile **final submitted, filtered source files** with fragment membership and refinement, including generated files, intermediate/sibling fragments and exclusions; do not infer the invocation from directory scans. Preserve static-linkage semantics. |
| [`StubCompilerPlugin.kt`](../../src/main/kotlin/net/msrandom/stub/StubCompilerPlugin.kt) and [`FirExpectTransformer.kt`](../../src/main/kotlin/net/msrandom/stub/fir/FirExpectTransformer.kt) | Keep normal KSP-discovered registrar/FIR/IR registration. Consume only verified invocation input and pre-bound fragment/module identity before converting an expect; UNKNOWN must never mean absent. Share the decision with the existing enum generator and IR stub body path rather than bypass native checking. |

The candidate handoff is one per-invocation internal snapshot/certificate, not a public toggle. It must describe the exact submitted file set and refinement, actual effective **content** consumed by native source collection, classpath/compiler options and admitted extension set. Indexing a `File.readText()` copy while the compiler reads a preprocessed `VirtualFile` is not sharing content. Either make the index and native compilation consume the *same* snapshot/VirtualFiles, or prove a narrower host contract in which generation is complete and content-changing extensions and in-flight changes cannot occur. A task input hash or `controlledInput=true` alone cannot prove either path. Verify final `KotlinCompile.sources` against emitted fragment options and KGP's collected inputs, not just two copies of configuration metadata.

Generated-source tasks must finish before final source/fragment membership and contents are certified and before any expect STATUS rewrite; retain `builtBy` dependencies and account for filtered/excluded files. Establish a complete mapping from all certified fragment files and refinement edges to the native `FirModuleData` objects **before the first irreversible absent decision**. Callback-by-callback identity checks cannot retract an earlier conversion if a later fragment conflicts. If the fixed compiler's session lifecycle cannot support this precondition, report that failure rather than asserting closure.

Admit the **effective** compiler registrar/extension set for these tasks, including KGP default scripting entries and the stub plugin. Check the fixed-version registrations and reject unsupported preprocessors, configuration-based source additions or declaration generators that can alter the indexed domain, unless their final effects are included in the same certified input. The project's own enum generator needs explicit accounting; non-stub jars are not automatically hostile, and a jar name alone does not prove safety. Start by disabling incremental compilation **only for the affected common stub KotlinCompile tasks**: it makes full-source assumptions testable but sacrifices incremental compile speed and may increase CPU/cache work. Restoring it requires separate proof that the incremental frontend's effective symbols, changed files and cached output are consistent with the certificate. This remains a proposed cost, not an already-configured production setting.

## Consequences, gates and authority

The recommended choice at the time would have expanded internal Cloche/virtual-source-sets ownership, coordination and version-sensitive verification but avoided a second full pipeline or shadow session. Remaining within the accepted plugin-only ownership avoided those changes and later passed the recorded P4 fixture gate. Neither choice reduced the Spec's declaration/diagnostic coverage.

If approved, first update the owning Spec boundary and record the architecture decision (ADR if the internal host/compiler ownership and extension admission become durable), then derive an updated Plan/Tasks. A bounded delivery order is: (1) establish version-pinned source/content/fragment identity and extension admission on existing Gradle stub tasks, with generated actual and the real preprocessor rejection-or-correct-retention witness, full-input versus incremental behavior; (2) complete ordinary source classifier and top-level `val`/`var`/extension-property missing-only semantics, retaining incompatible and orphan diagnostics; (3) integrate normal registrar/KSP packaging; (4) run fresh compiler/Gradle assertions for **every A1-A15 variant**, including descriptors, bodies, negative source diagnostics, class/member/enum/typealias behavior, then separately report the root-build status. No gate is passed by this proposal or by isolated green probes. Same-scope work under the accepted contract needs no new routine approval; **only the ownership/architecture expansion needs the user's decision**.

Open feasibility questions: whether the pinned host/compiler can share a genuinely final native content snapshot and pre-bind every relevant fragment identity before STATUS; which actual default extensions must be admitted; and whether admission can be enforced without a second driver. Failure on these points is a blocker to this direction, not license to silently add a compiler hook, upgrade, suppress diagnostics, or narrow A1-A15.

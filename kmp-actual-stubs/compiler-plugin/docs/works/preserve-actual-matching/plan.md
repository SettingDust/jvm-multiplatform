## Minimum implementation strategy

1. **Establish the product invocation and reuse its existing data.** Apply the real Cloche plugin in a disposable test fixture with parent and child common targets. Resolve task names from their common compilations rather than assuming `compileKotlin`. Record actual sources, fragment/refinement options, generated-source dependencies, plugin classpath, compiler artifact, and incremental mode at execution. Add a downstream target so the child actual is in an intermediate common fragment. The source path is `TargetApplicator` common `dependsOn` -> `Linkage.addSourceDependency` -> virtual-source-sets `addKotlinCommonSources` -> the ordinary KotlinCompile with the stub registrar. These source links already exist.
2. **Prove the narrow invocation contract in the plugin.** Start with `CompilerConfiguration` Kotlin roots, HMPP structure, native collected sources and `sourcesToPathsMapper`, or a verified fixed-version equivalent. Establish exact participating files/content and file-to-fragment/refinement identity before an irreversible missing decision. Include intermediate actuals, exclusions, generated files, and native ancestry/dominator filtering; `isCommon=false`, directory scans, filename tails, and empty future providers are insufficient. Check the fixed compiler's session/module construction relation, not just later callback names. A source-backed construction guarantee is acceptable; an artificial pre-binding table of all future FIR objects is not mandatory. Later callback checks alone do not repair an earlier wrong conversion.
3. **Limit extension/input checks to the actual build.** Inspect the effective registrar/extension registrations of the default KGP scripting components, the stub registrar/enum generator, and any actually configured source-changing component. KGP defaults appear in the saved plugin classpath; neither jar names nor `controlledInput=true` certify them. Normal source generation must finish first, and ordinary build inputs are assumed stable while compilation runs. If an actual source replacement/addition exists, consume its final effective output or reject that unsupported combination before modifying expect. Retain one executed preprocessor counterexample as a rejection-or-correct-input regression. Do not build a universal extension admission or immutable snapshot service for arbitrary IDE/third-party hosts.
4. **Make early preservation/missing decisions per compiler relationship.** Structured LightTree records may enumerate candidates; compiler semantics must govern distinctions. Internally distinguish potential legal candidate, proven absence, and unresolved input/semantics. Potential candidates keep original expect/actual for native binding, checking, and actualization. Bound return/member/alias incompatibility must remain an error. Only proven absence gets existing stub annotations and narrow missing-body allowances. Never force later resolve phases, treat UNKNOWN as absent, or suppress orphan/compatibility errors.
5. **Fix ordinary declarations first.** After complete candidate enumeration and legal owner/graph filtering, an empty relevant bucket proves absence without resolving a nonexistent candidate's full type header. This permits the missing `Token` function branch without weakening input guards. For nonempty parameter/receiver overload buckets, resolve ordinary source classifiers, import aliases, typealiases, type parameters/bounds and substitutions using phase-safe compiler-equivalent semantics; native-type Int/String evidence alone is insufficient. Prove equivalence against normal matching controls. Add top-level `val`, `var`, and extension properties with correct accessors. Do not filter away a property's incompatible type/mutability that native checking must reject. UNKNOWN that leaves any legal in-domain missing declaration failing is an incomplete implementation, not a delivered fallback.
6. **Keep class, enum, and IR ownership consistent.** A retained class retains its whole native member-checking obligation, including constructors, implicit members and nested declarations; never fill a missing actual member with a stub. Missing classes propagate the required stub treatment and shape to their members. The enum generator may request constructors at SUPERTYPES, before STATUS: it must use the same earlier decision/input as the transformer, and never generate a constructor for a retained enum. Actual typealias preserves native target/member checking with no competing class. Existing IR throws apply only to converted declarations/their applicable members or intentional explicit `@Stub`; retained actuals must not receive generated stub markings.

Choose the smallest internal implementation that satisfies these conditions. Do not promote ignored probe classes or their boolean/system-property controls unchanged into production. One bounded focused correction to an observed gate failure is appropriate; if the seam still lacks required phase/input/semantic information, record the smallest reproduction and stop dependent integration rather than accumulating unrelated experiments.

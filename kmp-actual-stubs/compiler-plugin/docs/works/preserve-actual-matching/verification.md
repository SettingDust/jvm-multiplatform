## Candidate evaluation

- **A, late semantic classification:** `PROBE/cases/pair-observer/phases.log` shows the common and platform STATUS callbacks with `mapping=null`. The platform checker later sees the valid actual's successful binding, but `BASIC_CHECKER_ORDER` puts the built-in expect/actual checker before the probe checker. `PROBE/cases/missing-observer/phases.log` shows an empty map at platform checking and no `IR_EXTENSION` after `NO_ACTUAL_FOR_EXPECT`. A checker callback is not an established legal mutation point that can convert only proven-absent declarations before diagnostics/IR. Absence of STATUS mapping is not evidence of a missing actual.
- **B, missing-symbol provider:** `PROBE/probe-src/ObservationPlugin.kt` compiles `MissingProviderApiWitness : IrMissingActualDeclarationProvider`, but only registers status/checker/IR observation extensions. It does **not** register or inject that provider, and no `CUSTOM_PROVIDER_CALLED` trace exists. The inspected compiler 2.2.20 sources at `PROBE/sources/org/jetbrains/kotlin/fir/pipeline/convertToIr.kt` initialize `LenientModeMissingActualDeclarationProvider` through the lenient flag, not an ordinary plugin provider registry; `PROBE/sources/main/kotlin/org/jetbrains/kotlin/backend/common/actualizer/ExpectActualCollector.kt` can call the provider for missing **or incompatible** candidates. Strict frontend errors already prevent the missing probe from entering IR. `PROBE/binary-api.log` records the accessible type/interface surface, not actual injection. Global lenient mode or pipeline replacement is not an accepted workaround.

Neither candidate meets the Plan's go criteria for strict diagnostics, phase safety and complete declaration coverage. No bounded boundary-witness suite or full A1–A15 matrix was run. A future in-scope mechanism requires new executable evidence of a safe integration point and missing-only semantics across the accepted surface. Otherwise an explicit decision must address architecture or version/scope; do not default to an upgrade, weaker diagnostics, reduced coverage or replacement compilation pipeline. Existing implementation authorization needs no duplicate approval gate for the same scope once its technical prerequisite is met.
